# CS-Weekly-Item-Journal runtime dependencies
#
# Supported: Python 3.11, 3.12, 3.13
#
# NOTE ON torch: `pip install -r requirements.txt` pulls the default PyPI
# torch build. On Linux that is the CUDA build (~2.5 GB). This app only ever
# runs inference on small crops, so the CPU build is plenty and ~200 MB:
#
#   pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
#
# See README.md "Installation" for the full walkthrough.
#
# Last verified working set (Python 3.12.7, Windows, CPU):
#   torch 2.13.0+cpu   torchvision 0.28.0   ultralytics 8.4.121
#   easyocr 1.7.2      numpy 2.5.2          opencv-python 4.14.0.94
#   Flask 3.1.3        Werkzeug 3.1.8       APScheduler 3.11.3
#   Pillow 12.3.0      requests 2.34.2      python-dotenv 1.2.3
# Models/BOX_TRAINED.pt loads and the golden-image test passes on that set.
# Also verified 2026-09-30 on Python 3.12.14, Linux, CPU: torch 2.14.0+cpu,
# ultralytics 8.4.166, opencv-python and opencv-python-headless 4.14.0.94.
# Also verified 2026-10-01 on Python 3.12, Linux aarch64, CPU: torch 2.14.1+cpu,
# ultralytics 8.4.171, easyocr 1.7.2, opencv 4.14.0.
# requirements.lock pins the exact set CI tests on Linux x86_64 / Python 3.12.

# --- Web framework ---
Flask>=3.0,<4
Werkzeug>=3.0,<4

# --- Deep learning runtime ---
# torch is a hard requirement of BOTH ultralytics and easyocr. It was missing
# from this file entirely, which let pip resolve an arbitrary build against a
# pinned-old numpy. It is now explicit.
torch>=2.2
torchvision>=0.17

# --- Image processing & ML ---
# ultralytics MUST be >=8.3.94. Models/BOX_TRAINED.pt is a YOLO11s checkpoint
# and its pickle references YOLO11-only modules (C3k2, C2PSA). Anything older
# -- the previous pin was 8.0.196, from Sept 2023 -- dies with
# "AttributeError: Can't get attribute 'C3k2'" while unpickling. That used to
# be a hard startup crash because the processor was built at import time; it is
# now constructed lazily (app.py get_processor()), but the pin is still the
# thing that makes detection work at all.
#
# ultralytics changes runtime behaviour even in patch releases: 8.4.171 began
# replacing PIL.Image.open and pip-installing pi-heif on demand. The weekly CI
# run and requirements.lock exist to catch that. The upper bound makes a new
# minor series a reviewed bump: raise it once CI passes against that series,
# then regenerate requirements.lock.
ultralytics>=8.3.94,<8.5
easyocr>=1.7.2
# Two OpenCV distributions end up installed and both write the same `cv2`
# package: ultralytics requires `opencv-python`, easyocr requires
# `opencv-python-headless` (unpinned). Left alone, headless resolved to 5.x
# next to opencv-python 4.x, so `cv2` was whichever wheel pip unpacked last --
# possibly a mix of both. Holding both to the same range makes pip pick the
# same release of each, so the overlapping files are identical and install
# order stops mattering. tests/test_config.py checks the versions match.
opencv-python>=4.9,<5
opencv-python-headless>=4.9,<5

# numpy 1.24.4 shipped wheels for cp38-cp311 only, so pip could not even
# install it on Python 3.12/3.13. 1.26 is the first release with cp312 wheels.
numpy>=1.26,<3
Pillow>=10.2

# --- HTTP ---
requests>=2.31

# --- Configuration ---
python-dotenv>=1.0

# --- Scheduling ---
APScheduler>=3.10,<4
